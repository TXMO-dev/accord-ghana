Migration to asymmetric JWT signing must match a signing key explicitly trusted by Supabase.

Design:
- Wallet signs a domain-, network-, deployment-, agreement-, nonce- and expiry-bound SEP-53 message.
- Server verifies signature and reads the agreement from Stellar Testnet before granting access.
- Only standard single-key accounts are currently supported. No payment is signed at room login.
- Nonces are consumed atomically; sessions are hashed in storage, scoped to one room, expire after 30 minutes.
- Client and freelancer can read the latest 100 comments and recently-active presence.
- Comments use plain text, 1500-character limit, idempotency IDs and per-wallet rate limits.
- Anonymous/authenticated direct table reads and writes are denied. Only the server's RPC role accesses storage.
- Private WebSocket notifications contain only an invalidation signal. Clients reread through the authenticated API.
- WebSocket tokens expire after 30 minutes; after leaving, an old token can receive invalidation signals until expiry, never comment bodies.
- Presence is a recent heartbeat, not proof that someone is actively watching. No live avatar position sync is claimed.
- Periodic refresh works if WebSockets disconnect. Financial state always comes from Stellar, not chat.
- Data is stored on the service; it is not end-to-end encrypted. Keep sensitive work files elsewhere.
- First release has no attachments, edits/deletes, typing indicators, or moderation dashboard.

Activation acceptance checklist (must be performed before claiming live multiplayer):
- Two real Varial Testnet accounts join the same agreement from separate browsers.
- An unrelated third account and unsigned/tampered/expired/replayed challenges are denied.
- A comment arrives over the private channel without reload; reconnect uses periodic fallback.
- Confirm switching wallet/room clears comments, session and presence.
- Confirm leaving removes API access; test session expiration and network failure.
- Confirm no browser response, source map, or build asset contains server secrets.
- Confirm milestone celebrations occur only on newly verified forward state changes.

No mainnet funding, loan eligibility, or production security audit is implied by this feature.
